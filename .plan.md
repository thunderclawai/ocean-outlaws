# Plan: Ship collision slide & enemy terrain avoidance

## Issue
#148 — Ships (player, enemy, boss) get stuck on island terrain collisions. Collision response pushes ships into geometry instead of sliding along surfaces. Enemy AI blindly runs into islands.

## Analysis

### Current collision system
The collision pipeline works as follows:

1. **`terrainComposite.js:resolveVisualCollision`** (line 474) — the primary collision resolver when `useVisualCollision` is true (most maps). It iterates AABB colliders and pushes the ship out along the shortest axis. This is a hard stop — it snaps the position to the nearest box edge with no velocity adjustment. The ship's heading and velocity are unchanged, so next frame it just moves back into the same collider face → **stuck loop**.

2. **`terrain.js:collideWithTerrain`** (line 223) — the wrapper that delegates to `resolveVisualCollision` for visual terrain, or uses heightmap gradient push for procedural terrain. The heightmap path has the same problem: it pushes position but doesn't modify heading or project velocity.

3. **`ship.js:updateShip`** (line 312) — after movement, calls `collideWithTerrain`. On collision, it sets `speed *= 0.45` and clamps negative speed to 0. No heading adjustment, no slide vector. Ship just decelerates into the wall.

4. **`enemy.js:updateEnemies`** (line 433) — enemy collision is even worse: on collision it just sets `posX/posZ = col.newX/newZ` with **zero speed reduction and zero heading adjustment**. The enemy immediately moves back into the wall next frame.

5. **`boss.js:updateBoss`** (line 360) — identical to enemy: position snapped, no speed/heading adjustment.

### Current terrain avoidance
- **Player ship** (`ship.js` line 222) — has `getTerrainAvoidance` that steers away from nearby colliders with a configurable range. This partially works but isn't strong enough.
- **Enemies** — have **zero** terrain avoidance. They steer purely toward/away from the player with no obstacle awareness.
- **Bosses** — have **zero** terrain avoidance.

### Root causes of getting stuck
1. `resolveVisualCollision` pushes along shortest-axis but doesn't project velocity onto the slide surface
2. No heading adjustment on collision — ships keep pointing into the wall
3. No stuck detection/recovery mechanism
4. Enemies/bosses have no proactive terrain avoidance at all

## Changes

### game/js/collision.js (create)
New shared module for slide-along collision response and stuck detection, used by ship, enemy, and boss.

- **`slideCollision(terrain, posX, posZ, prevX, prevZ, heading, speed, dt)`** — core slide-along function:
  - Call `collideWithTerrain` to detect collision
  - If collided, compute collision normal from the AABB face that was penetrated
  - Project the velocity vector onto the surface tangent (perpendicular to normal)
  - Return `{ collided, newX, newZ, slideHeading, slideSpeed }` with the slid position and adjusted heading/speed
  - Push ship outward from collision normal by a small margin (0.1 units) to prevent re-penetration
  - Reduce speed by 30% on collision (not 55% like current) to keep ships moving along the wall

- **`createStuckDetector()`** — returns a stuck state tracker:
  - Tracks position history over a rolling 3-second window
  - `updateStuck(posX, posZ, dt)` — accumulates distance traveled
  - `isStuck()` — returns true if total displacement over 3 seconds < 2 units (essentially not moving)

- **`nudgeToOpenWater(terrain, posX, posZ, heading)`** — teleport recovery:
  - Use `findWaterPosition` from `terrain.js` to find nearest open water
  - Returns `{ x, z }` of safe position
  - Search in expanding rings starting from current heading ± 90° (prefer forward directions)

## Risks
- **Slide direction ambiguity at corners**: When two AABB faces meet at a corner, the ship could oscillate between slide directions. Mitigation: the iterative loop in `resolveVisualCollision` (4 iterations) already handles multi-collider resolution — we use the final resolved position's net displacement as the slide direction.
- **Stuck detector false positives**: Ships that are legitimately stationary (e.g., waiting at a port, no nav target) could trigger stuck detection. Mitigation: only activate stuck detection when the ship has a non-zero speed or nav target.
- **Performance**: `getTerrainAvoidance` iterates all visual colliders. With 30+ colliders and 12 enemies, this is 360 checks per frame — negligible overhead.
- **Boss size**: Bosses have larger hitRadius (4-6 units). The slide collision margin and avoidance range need to account for this. Using a larger avoidance range (22 vs 18) for bosses addresses this.
- **File size**: `enemy.js` is currently 687 lines. Adding ~30 lines of avoidance/collision keeps it under 500 if we can trim elsewhere, but may require a follow-up split. The new `collision.js` module keeps shared logic out of individual files.
