# Plan: Rework merchants: ambient world spawns, not combat wave enemies

## Issue
#152 — Remove merchants from combat wave rotation; spawn them as ambient world entities sailing trade routes that players can optionally attack for loot.

## Analysis

### Current state
Merchants are regular combat wave enemies. `FACTION_ROTATION` in both `wave.js` (line 20) and `mapData.js` (line 195) places merchants at indices 2 and 6, meaning waves 3 and 7 are merchant waves. Since merchants flee the player and get a 1.3x panic speed burst (`enemy.js:402`), these waves are frustrating — the wave won't end until all enemies are dead but merchants are hard to catch.

### Key files and how they work
- **`game/js/wave.js`** — Wave state machine. `FACTION_ROTATION` array drives which faction spawns each wave. `buildWaveConfigs()` creates 10 wave configs cycling through the rotation.
- **`game/js/mapData.js`** — Zone-based play. Has its own duplicate `FACTION_ROTATION` (line 195) used by `buildZoneWaveConfigs()`.
- **`game/js/enemy.js`** (744 lines) — `FACTIONS` object defines merchant stats (speed: 10, goldMult: 3.0). Merchant AI at line 399 flees player; panic burst at dist < 15. Firing restricted to "cornered" scenarios (line 520). `spawnEnemy()` at line 273 is gated by wave manager's `canSpawn`/`consumeSpawn`.
- **`game/js/main.js`** (1584 lines) — `buildNodeWaveConfigs()` at line 823 handles voyage chart nodes; `merchant_chase` node type gets reduced waves but still uses `"merchant"` faction. Death callback at line 138 awards gold via `getFactionGoldMult()`.
- **`game/js/voyageData.js`** — `NODE_TYPES.merchant_chase` (line 10) with weight 15 in node pool (line 170).
- **`game/js/voyageChart.js`** — Visual chart renderer, references `merchant_chase` in icon/legend.
- **`game/js/pickup.js`** — Drop system: random type (ammo/fuel/gold/parts). No faction-aware drops.
- **`game/js/crate.js`** — Good reference for ambient spawning pattern: timer-based, independent of waves, terrain-aware positioning.
- **`game/js/ship.js`** — Player speeds: Sloop 14, Brigantine 10, Galleon 7, Man-o'-War 5. Merchant base speed is 10 (same as Brigantine).

### Speed math
Issue says merchants should be 50-70% of player max speed. Player max varies by ship class (5–14). The simplest approach: merchant base speed = 6 (catches the sweet spot for most classes). With Sloop (14): merchant is 43%. With Brigantine (10): 60%. With Galleon (7): 86% — too high. Better approach: make merchant speed relative to the player's ship class at spawn time, e.g. `playerMaxSpeed * (0.5 + random * 0.2)`.

### What doesn't exist yet
- No ambient entity system independent of waves
- No trade route / waypoint / patrol path infrastructure
- No merchant-specific loot table (just generic pickup + gold multiplier)
- No convoy system (grouped merchants + escorts)

## Changes

### game/js/merchant.js (create)
New file — ambient merchant spawn and update system (~300 lines). Modeled after `crate.js` pattern but with moving ships.

**Constants:**
- `SPAWN_INTERVAL_BASE = 25` — seconds between spawn checks
- `SPAWN_INTERVAL_MIN = 12` — minimum interval at high zones
- `MAX_MERCHANTS = 6` — concurrent ambient merchants
- `MERCHANT_LIFETIME = 120` — seconds before a merchant despawns (sailed off-map)
- `SPEED_RATIO_MIN = 0.5`, `SPEED_RATIO_MAX = 0.7` — fraction of player max speed
- `FLEE_SPEED_RATIO = 0.85` — flee speed as fraction of player max (always catchable)
- `CONVOY_CHANCE = 0.2` — 20% chance a spawn is a convoy
- `CONVOY_SIZE = [2, 3]` — ships in a convoy
- `ESCORT_FACTION = "navy"` — convoy escorts
- `MAP_HALF = 200` — map boundary
- `TRADE_ROUTE_MARGIN = 30` — spawn/despawn distance from map edge
- `AGGRO_RANGE = 25` — distance at which attacked merchant starts fleeing toward player

**Key exports:**
- `createMerchantManager()` — returns `{ merchants: [], spawnTimer, playerMaxSpeed: 10 }`
- `updateMerchants(mgr, ship, dt, scene, terrain, elapsed, getWaveHeight, enemyMgr, zone)` — tick spawn timer, move merchants along routes, handle flee AI, check despawn/off-map
- `clearMerchants(mgr, scene)` — remove all (for scene transitions)
- `setMerchantPlayerSpeed(mgr, speed)` — called when player class changes, so merchant speed scales correctly
- `getMerchantCount(mgr)` — for HUD/minimap

**Trade route system:**
- On spawn, pick two edge points on opposite sides of the map (e.g., north edge → south edge, or NE → SW)
- Merchant sails in a straight line between waypoints with terrain avoidance (reuse `getTerrainAvoidance` from `terrain.js`)
- When reaching destination edge or lifetime expires, despawn gracefully (sail off-map)

**Flee behavior:**
- When `attacked` flag is set, switch from trade route AI to flee AI (same as current enemy.js merchant logic but capped at `FLEE_SPEED_RATIO * playerMaxSpeed`)
- Remove panic burst — flee speed is always < player speed
- Merchant still fires when cornered (rear angle logic preserved)

**Loot on death:**
- Merchants use the existing `onDeathCallback` mechanism from enemy.js (they ARE enemies in the enemy manager, just spawned by the merchant system instead of the wave system)
- Enhanced drop: always drop 2 pickups instead of 1 (extra gold + supply crate)
- Gold multiplier stays at 3.0

**Convoy spawning:**
- 20% chance each spawn rolls a convoy instead of a single merchant
- Convoy = 2-3 merchant ships spawned at same edge point, sailing same route with slight offset
- 1 navy escort ship spawned alongside (using existing navy faction stats)
- Escort uses navy AI (circle strafe, broadside) — hostile only if player attacks a convoy member

**Zone scaling:**
- Spawn interval decreases with zone difficulty: `SPAWN_INTERVAL_BASE - zone.difficulty * 2` (clamped to min)
- More merchants in higher zones = more opportunity

**Integration with enemy.js:**
- Ambient merchants are added to `enemyMgr.enemies` array (they're the same data structure)
- But they are NOT gated by wave `canSpawn`/`consumeSpawn`
- New field on enemy object: `ambient: true` — so wave manager ignores them when counting `enemiesAlive`
- New field: `tradeRoute: { startX, startZ, endX, endZ }` for patrol pathfinding
- New field: `attacked: false` — flips to true on first damage, triggers flee AI

## Testing

- **Wave completion:** Start a game, verify all 10 waves are pirate/navy only. Waves 3 and 7 (previously merchant) should now be pirate/navy per the new rotation. All waves should complete without chase frustration.
- **Merchant spawning:** Verify merchant ships appear sailing across the map between/during combat waves. Check they appear at map edges and sail toward the opposite edge.
- **Speed check:** With a Sloop (speed 14), merchant should be visibly slower (speed ~7-10). With Brigantine (speed 10), merchant should be ~5-7. Player should always be able to catch merchants.
- **Flee behavior:** Attack a merchant — it should flee but NOT outrun the player. No panic speed burst.
- **Loot drops:** Destroying a merchant should drop 2 pickups + gold reward (3x multiplier preserved).
- **Convoys:** Over several minutes of play, at least one convoy should spawn (2-3 merchants + navy escort). Escort should be hostile only after player attacks.
- **Zone scaling:** In higher-difficulty zones, merchants should spawn more frequently.
- **Voyage chart:** `merchant_chase` nodes should still work — lighter combat encounter with ambient merchants in scene.
- **Scene transitions:** Merchants should be cleaned up when switching between menus, zones, or voyage nodes.
- **Wave alive count:** Ambient merchants should NOT block wave completion. Verify waves end even if ambient merchants are alive on the map.

## Risks

- **enemy.js is 744 lines** — close to the 500-line limit in FACTORY.md. Adding the ambient spawn function and trade route AI branch will push it further. May need to extract merchant AI into `merchant.js` to keep enemy.js focused.
- **Alive count bug potential** — If the `ambient` flag check is missed anywhere in wave/enemy counting, merchants could block wave progression (the exact bug we're fixing). Need to audit all places `enemiesAlive` is referenced.
- **Multiplayer sync** — Ambient merchants need to be synced in multiplayer. The existing `sendEnemyState`/`applyEnemyStateFromHost` in `netSync.js`/`combatSync.js` already syncs the enemies array, but ambient merchants spawned by the host need to appear on clients. The `ambient` and `tradeRoute` fields need to survive serialization.
- **Man-o'-War balance** — Man-o'-War max speed is 5. Even at 50% ratio, a merchant at 2.5 speed seems too slow to be interesting. May need a minimum merchant speed floor (e.g., 4) so they don't feel stationary.
- **Convoy escort aggro** — The navy escort should only become hostile when the player attacks the convoy. This requires tracking convoy membership and triggering aggro on nearby escorts — a new mechanic that doesn't exist yet. Simplest approach: spawn escorts as regular navy enemies but with `ambient: true` and a `convoyId` field; when any convoy member is attacked, set `attacked: true` on all members sharing the same `convoyId`.
