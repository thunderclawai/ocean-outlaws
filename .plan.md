# Plan: Rework upgrades to in-game card picker + crew as passive pickups

## Issue
#146 — Replace between-wave upgrade/crew screens with mid-combat card picker, add port nodes to voyage chart, and turn crew members into in-game passive pickups.

## Analysis

### Current Between-Wave Flow
When a wave completes in `main.js` (lines ~1374-1405), the game:
1. Shows `upgradeScreen.js` — full blueprint shop where player spends gold on tiered upgrades
2. On close → calls `applyUpgrades()` → shows `crewScreen.js` for officer station assignment
3. On close → resumes game audio and unpauses

The same sequence happens after roguelite node victory (lines ~1438-1454), except it also transitions back to the voyage chart afterward.

### Current Upgrade System
- `upgrade.js` defines UPGRADE_TREE: 4 categories × 3 upgrades × 3 tiers, all gold-purchased
- `upgradeScreen.js` (416 lines) is a full-screen overlay with category panels and buy buttons
- `portScreen.js` (472 lines) is a near-duplicate for port shop (repair + upgrades)

### Current Crew System
- `crew.js` defines 4 stations (weapons/engine/helm/medical), officers with specialty + rank
- Officers generated via `generateOfficerReward(rank)` with procedural names/portraits
- `crewScreen.js` (341 lines) is a full-screen overlay for roster management + station assignment
- Officers currently auto-recruit: 50% chance on wave complete (rank 1), guaranteed on boss defeat (rank 2-3)
- Bonuses: matching specialty = full bonus, mismatched = half

### Current Voyage Chart
- `voyageData.js` defines 6 node types: fleet_battle, harbor_raid, merchant_chase, salvage, storm_crossing, event, boss
- **No port node type exists** — ports are only physical terrain objects
- Chart has 7 columns, 1 start node, 2-4 middle nodes per column, 1 exit node

### Current Pickup System
- `pickup.js` handles ammo/fuel/parts/gold drops from enemies
- 3D floating meshes with bob, glow, spin, proximity collection
- **No crew pickup type exists**

### Key Integration Points
- `main.js` lines ~1307-1318: Boss defeated → rollBossLoot + auto-recruit officer
- `main.js` lines ~1385-1389: Wave complete → 50% chance recruit officer
- `main.js` line 111: `gameFrozen` controls pause state
- `main.js` line 112: `upgradeScreenOpen` blocks input during screens
- `buildCombinedMults()` in upgrade.js combines upgrade + crew + tech bonuses

## Changes

### game/js/cardPicker.js (create)
- **Purpose**: Mid-combat card picker UI overlay (Vampire Survivors style)
- **Exports**: `createCardPicker()`, `showCardPicker(cards, onPick)`, `hideCardPicker()`, `isCardPickerVisible()`
- **DOM structure**: Fixed overlay (z-index 90) with semi-transparent dim background, 3 card elements in a centered row
- **Card layout**: Each card is a styled div with icon (large emoji/symbol), upgrade name (bold), one-line stat description, category color border
- **Interaction**: Click/tap a card → calls `onPick(selectedCard)` → auto-hides
- **Mobile**: Cards stack vertically, min-height 44px touch targets, responsive sizing
- **Style**: Match existing parchment/nautical theme (use T, FONT, PARCHMENT_BG from theme.js)
- **Animation**: Cards fade in with slight scale-up, selected card briefly highlights before closing

### game/js/cardGen.js (create)
- **Purpose**: Generate random card options from the upgrade pool
- **Exports**: `generateUpgradeCards(upgradeState, count)` — returns array of `count` card objects
- **Card object**: `{ type: "upgrade", key: "damage", category: "weapons", label: "+Damage", desc: "+20% damage", icon: "⚔", color: "#ffaa22", tier: 2 }`
- **Logic**:
  - Collect all upgrades not yet maxed (level < 3)
  - Shuffle and pick `count` (default 3), ensuring no duplicates
  - If fewer than `count` available, return what's available
  - Each card represents a FREE tier upgrade (not gold-cost) — this is the core change from the current shop model
- **Imports**: `getUpgradeTree` from upgrade.js, `nextRandom` from rng.js
- **Icons map**: Map each upgrade key to a descriptive icon/emoji for card display

### game/js/crewPickup.js (create)
- **Purpose**: Crew member as 3D in-game pickup (Diablo-style loot drop)
- **Exports**: `createCrewPickupManager()`, `spawnCrewPickup(mgr, x, y, z, scene, officer)`, `updateCrewPickups(mgr, ship, dt, elapsed, getWaveHeight, scene)`, `clearCrewPickups(mgr, scene)`
- **3D model**: Distinct from resource pickups — use a small figure/bust mesh or unique colored gem, with crew-colored glow (gold/purple)
- **Collection**: Proximity-based like resource pickups, but triggers crew add flow
- **On collect**: Returns the officer object to the caller (via callback) for main.js to handle add/swap
- **Bob/glow/spin**: Reuse pickup.js patterns but with distinct visual (larger glow, different color)

### game/js/crewHud.js (create)
- **Purpose**: Display crew roster as small HUD icons in top-left corner (below HP/fuel bars)
- **Exports**: `createCrewHud()`, `updateCrewHud(crewState)`, `destroyCrewHud()`
- **Layout**: Row of small circular icons (crew portraits/emojis), max 8
- **Tooltip**: On hover (desktop) or tap (mobile), show officer name, specialty, rank, bonus
- **Style**: Semi-transparent background, matches existing HUD aesthetic
- **Position**: Below the port proximity label in the top-left panel

### game/js/crewSwap.js (create)
- **Purpose**: Quick in-game overlay for crew swap when roster is full (max 8)
- **Exports**: `createCrewSwap()`, `showCrewSwap(currentRoster, newOfficer, onChoice)`, `hideCrewSwap()`
- **UI**: Small overlay showing new officer vs current roster, player taps to swap or discard
- **Design**: Compact card layout — new officer on left, existing roster on right, tap existing to replace or tap "discard" to skip
- **Mobile-friendly**: Large touch targets, minimal UI

## Risks
- **Multiplayer sync**: Card picker is local per-player (each picks independently) — must ensure `cardPickerOpen` blocks input correctly. The current `upgradeScreenOpen` pattern is the model.
- **Balance shift**: Free card upgrades instead of gold-purchased upgrades fundamentally changes economy. Gold becomes port-shop-only currency. May need tuning of gold drop rates or port shop prices.
- **500-line limit**: `main.js` is already very large. Adding card picker + crew pickup wiring may push it further. May need to extract helper functions into a `gameFlow.js` or similar.
- **Crew auto-assignment**: Players lose manual station control. The auto-assign should be smart (matching specialty → empty station → skip if no benefit). Swap overlay partially mitigates.
- **Port node rarity**: With weight 10 out of ~120 total, ports appear ~8% of nodes. May need tuning if too rare or too common.
- **Removing upgradeScreen.js**: The `portScreen.js` handles port shop purchases, but if any code path still references `showUpgradeScreen`, it will break. Must audit all callers.
- **save.js compatibility**: Saved runs with old format (crewAssigned as station assignments) should still load correctly since crew.js structure doesn't change, just adds new functions.
