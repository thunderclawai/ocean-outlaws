# Plan: Bug: legacy terrain/land objects still spawning alongside Palmov compositions

## Issue
#147 — Remove legacy heightmap-based terrain generation and collision so only Palmov composition-based terrain is active.

## Analysis

PR #173 (commit `23a76d2`, already on this branch) did the first pass:
- Removed `buildTerrainMesh()` and all marching-squares mesh helpers (~170 lines)
- Removed dead constants (`TERRAIN_HEIGHT`, `BEACH_HEIGHT`, `BOUNCE_STRENGTH`, `TERRAIN_VISUAL_Y_OFFSET`)
- Fixed `isLand()` / `getTerrainHeight()` so they don't leak through to heightmap when `useVisualCollision` is true
- Removed `baseMesh` from `createTerrain()` — no green procedural mesh is ever added to the scene

**What remains (the bug surface):** The full heightmap generation pipeline (~180 lines of noise, blur, heightmap code) is still present and still runs on every zone load. More critically, during the async window before `addCompositeFieldVisual` completes and sets `useVisualCollision = true`, all collision/query functions fall through to the invisible heightmap. This creates phantom collisions with terrain that has no visual representation — ships and enemies bounce off invisible walls that don't correspond to any Palmov island.

### Key files and current roles:

- **`terrain.js`** (411 lines) — Public API (`isLand`, `collideWithTerrain`, `terrainBlocksLine`, `getTerrainHeight`, `findWaterPosition`, `createTerrain`, etc.). Still contains full heightmap pipeline: `hashCoord`, `smoothstep`, `noise2D`, `fbm`, `gaussianBlur`, `generateHeightmap`, `ensureNavigable`, `sampleHeight`, plus all collision fallback paths.
- **`terrainComposite.js`** (588 lines) — Palmov composition system. `addCompositeFieldVisual` loads FBX islands from preset JSONs. `addTieredIslandFieldVisual` is the fallback that uses `collectLandPoints(heightmap)` to seed island placement when compositions fail to load.
- **`port.js`** — `findCoastlinePositions()` calls `getTerrainHeight()` and `isLand()` synchronously, immediately after `createTerrain()`, before async compositions load. This is the main reason the heightmap was kept — ports need it for coastline detection during the async window.
- **`ocean.js`** — `setTerrainMap` / `clearTerrainMap` set `uHasTerrain` uniform based on `terrain.heightmap`. This uniform is defined but never consumed by the CPU vertex-color ocean — it's a dead vestige of a previous GPU shader approach.
- **`main.js`** — Calls `createTerrain()` then immediately `initPorts()` and `setTerrainMap()`. Pattern repeats in 3 places (multiplayer start, voyage node, zone enter).
- **`collision.js`**, **`enemy.js`**, **`boss.js`**, **`ship.js`**, **`weapon.js`**, **`nav.js`**, **`merchant.js`**, **`crate.js`** — All consume `isLand` / `collideWithTerrain` / `terrainBlocksLine` from terrain.js. These don't need changes; they call the public API.

### The heightmap dependency chain:
1. `createTerrain()` calls `generateHeightmap()` + `ensureNavigable()` synchronously
2. `initPorts()` is called immediately after, uses `getTerrainHeight()` / `isLand()` which fall through to heightmap (since `useVisualCollision` is still false)
3. Async: `addCompositeFieldVisual()` loads FBX compositions, then sets `useVisualCollision = true`
4. If compositions fail: `addTieredIslandFieldVisual()` uses `collectLandPoints(heightmap)` for seeded placement

### Strategy:
- **Keep** heightmap generation but make it private/internal — only used by port placement and tiered fallback seeding
- **Remove** all heightmap fallback paths from public collision/query functions
- **Add** dedicated internal functions for port heightmap queries
- **During async window**: collision returns "open water" (no collision) rather than phantom heightmap walls
- **Remove** dead ocean terrain map code

## Changes

### terrain.js (modify)

**Remove heightmap collision fallback from `isLand()` (line 207):**
- When `useVisualCollision` is false, return `false` instead of falling through to `sampleHeight`
- This eliminates phantom heightmap collisions during async loading

**Remove heightmap collision fallback from `getTerrainHeight()` (line 214):**
- When `useVisualCollision` is false, return `-1` instead of falling through to `sampleHeight`
- This also breaks port placement — see new export below

**Remove heightmap collision fallback from `collideWithTerrain()` (lines 226-258):**
- Delete the ~30-line heightmap gradient sampling + push-back block after the `useVisualCollision` branch
- When visual collision returns null and heightmap path is removed, just return no-collision
- `CELL_SIZE` constant becomes dead — remove it

**Remove heightmap LOS fallback from `terrainBlocksLine()` (lines 278-292):**
- Delete the ~15-line heightmap sampling loop after the `useVisualCollision` branch
- When visual collision is not active, return `false` (no blocking)

**Add new export `sampleHeightmap(terrain, x, z)` for port placement:**
- Thin wrapper around `sampleHeight` that checks `terrain.heightmap` exists
- Only used by port.js for coastline detection during async window
- Keep `sampleHeight` as internal function

**Add new export `isHeightmapLand(terrain, x, z)` for port placement:**
- Returns `sampleHeight(terrain, worldX, worldZ) > SEA_LEVEL`
- Only used by port.js for coast scanning

**Clean up dead constants:**
- Remove `CELL_SIZE` (was only used by heightmap collision gradient)
- Keep `MAP_SIZE`, `GRID_RES`, `SEA_LEVEL`, `SPAWN_CLEAR_RADIUS`, `COLLISION_RADIUS`, `VISUAL_COLLIDER_PAD` — still used
- Keep noise constants (`NOISE_SCALE`, `OCTAVES`, `PERSISTENCE`, `LACUNARITY`) — still needed by `generateHeightmap`

**Update module header comment:**
- Change from "procedural island generation, 3D mesh, collision queries" to "Palmov composition terrain, collision queries, map boundaries"

### port.js (modify)

**Switch from `getTerrainHeight` / `isLand` to heightmap-specific functions (lines 5, 37, 46, 59, 83):**
- Import `sampleHeightmap`, `isHeightmapLand` from terrain.js instead of `getTerrainHeight`, `isLand`
- Replace `getTerrainHeight(terrain, x, z)` → `sampleHeightmap(terrain, x, z)` (line 37, 83)
- Replace `isLand(terrain, ...)` → `isHeightmapLand(terrain, ...)` (lines 46, 59)
- This makes the port's heightmap dependency explicit and prevents it from breaking when the public API no longer falls through to heightmap

### ocean.js (modify)

**Remove dead terrain map functions and uniforms:**
- Remove `setTerrainMap()` function (lines 49-52) — `uHasTerrain` uniform is never read by the CPU ocean
- Remove `clearTerrainMap()` function (lines 54-57)
- Remove `uHasTerrain` and `uTerrainMap` from `createCompatUniforms()` (lines 14-15)

### main.js (modify)

**Remove all `setTerrainMap` / `clearTerrainMap` calls:**
- Remove import of `setTerrainMap`, `clearTerrainMap` from ocean.js (line 2)
- Remove `setTerrainMap(ocean.uniforms, activeTerrain)` calls (lines 708, 927, 1053)
- Remove `clearTerrainMap(ocean.uniforms)` from all terrain cleanup blocks (lines 254, 702, 921, 1017, 1044, 1170)

## Order of Operations
1. **terrain.js** — Add `sampleHeightmap` and `isHeightmapLand` exports; remove heightmap fallbacks from `isLand`, `getTerrainHeight`, `collideWithTerrain`, `terrainBlocksLine`; remove `CELL_SIZE`; update header comment
2. **port.js** — Switch imports to `sampleHeightmap` / `isHeightmapLand`
3. **ocean.js** — Remove `setTerrainMap`, `clearTerrainMap`, dead uniforms
4. **main.js** — Remove `setTerrainMap` / `clearTerrainMap` imports and calls

## Testing
- **Load game, enter a zone** — Palmov FBX composition islands should appear, no green procedural mesh, no invisible walls
- **Sail toward island during first 1-2 seconds of loading** — ship should pass through freely during async window (before compositions load), then collide normally once visual colliders are active
- **Check port spawning** — ports should still appear at coastline positions near islands (verify in at least 3 different seeds)
- **Composition load failure** — temporarily rename `compositePresetsPalmov30.json` to verify tiered fallback still places islands using heightmap seed data
- **Edge case: rapidly switching zones** — ensure cleanup path works without `clearTerrainMap` calls
- **Boss / enemy projectiles** — verify `terrainBlocksLine` still blocks correctly through visual island colliders
- **Enemy pathfinding** — enemies should navigate around visible islands, not get stuck on invisible heightmap terrain

## Risks
- **Port placement during async window** — ports use heightmap data before compositions exist. The new `sampleHeightmap` / `isHeightmapLand` exports preserve this behavior explicitly, but port positions may not align perfectly with visual islands since they're seeded from the heightmap. This is pre-existing behavior, not a regression.
- **Brief collision gap during async loading** — for ~0.5-2s while FBX assets load, there is no terrain collision at all. Ships/enemies can briefly pass through where islands will appear. This is acceptable and much better than colliding with invisible heightmap walls.
- **`addTieredIslandFieldVisual` fallback** — still receives the heightmap for seeded placement. If composition JSON fails to load, the tiered fallback still works. No change needed here.
