# Plan: Bug: bosses never spawn — wave configs missing boss assignments

## Issue
#153 — `buildWaveConfigs()` in wave.js generates 10 wave configs but never sets `.boss`, so bosses cannot spawn during default/multiplayer combat.

## Analysis

### How it works today
Three wave config builders exist:
1. **`buildWaveConfigs()`** (`wave.js:22-35`) — default 10-wave config, used for multiplayer and as fallback. **Never sets `.boss`** — this is the bug.
2. **`buildZoneWaveConfigs(zone)`** (`mapData.js:200-219`) — used for zone-based combat. Correctly sets `.boss` on the final wave using zone data.
3. **`buildNodeWaveConfigs(nodeType, col, totalCols)`** (`main.js:823-851`) — used for voyage chart nodes. Correctly sets `.boss` on final wave of "boss" node types.

### When the broken default is used
- `createWaveManager()` at init (`main.js:170`) — no external configs
- `startMultiplayerCombat()` (`main.js:656`) — `resetWaveManager(waveMgr)` with no external configs, **this is the primary bug path**
- `onNewGame` (`main.js:225`) and restart callback (`main.js:1092`) — transitional resets, overwritten when zone/node is selected

### Boss system (already working)
- `createBoss(bossType, playerX, playerZ, scene, zoneDifficulty)` (`boss.js:108-150`) — spawns boss, scales HP by `zoneDifficulty`
- Three boss types exist: `battleship` (Blackthorn, 80hp), `carrier` (Widow's Galleon, 60hp), `kraken` (The Kraken, 100hp)
- Boss spawn is triggered by `"wave_start_boss:<type>"` event from `updateWaveState()` (`wave.js:95-96`)
- Wave completion requires `activeEnemyCount === 0 && !bossAlive` (`wave.js:120`)
- Boss HUD (`bossHud.js`), loot drops (`boss.js:564-589`), officer rewards (`main.js:1282-1293`), and multiplayer sync (`combatSync.js`) all already work once a boss actually spawns

### Boss difficulty in main.js event handler
At `main.js:1332`, difficulty is computed as:
```
zone ? zone.difficulty : (currentNode ? 1 + Math.floor(col * 5 / 6) : 1)
```
When no zone/node context exists (multiplayer/default), difficulty hardcodes to 1. Need a fallback from the wave config itself.

## Changes

### game/js/wave.js (modify)

- **Add `MINI_BOSS_WAVE` constant** (line ~8 area): `var MINI_BOSS_WAVE = 5;` — defines which wave gets a mini-boss
- **Modify `buildWaveConfigs()` to accept optional `baseDifficulty` param** (line 22):
  - `function buildWaveConfigs(baseDifficulty)` with `baseDifficulty = baseDifficulty || 1;`
- **Set mini-boss on wave 5** (inside the loop, after building cfg):
  - When `i === MINI_BOSS_WAVE`: set `cfg.boss = "battleship"` (Blackthorn — pirate captain mini-boss)
  - Set `cfg.bossDifficulty = baseDifficulty`
  - Halve enemies: `cfg.enemies = Math.max(2, Math.floor(cfg.enemies / 2))`
- **Set zone boss on wave 10** (inside the loop, after building cfg):
  - When `i === MAX_WAVE`: compute `finalDifficulty = baseDifficulty + 2`
  - Boss type escalates with difficulty: `finalDifficulty >= 5 ? "kraken" : finalDifficulty >= 3 ? "carrier" : "battleship"`
  - Set `cfg.boss` and `cfg.bossDifficulty = finalDifficulty`
  - Halve enemies: `cfg.enemies = Math.max(1, Math.floor(cfg.enemies / 2))`
- With default `baseDifficulty = 1`: wave 5 gets battleship (diff 1), wave 10 gets carrier (diff 3) — good escalation
- With `baseDifficulty = 3`: wave 5 gets battleship (diff 3), wave 10 gets kraken (diff 5) — hard mode

### game/js/main.js (modify)

- **Boss spawn event handler** (`main.js:1329-1345`): Add `cfg.bossDifficulty` as fallback in the difficulty calculation at line 1332:
  ```
  var difficulty = zone ? zone.difficulty :
    (currentNode ? 1 + Math.floor(currentNode.col * 5 / Math.max(1, 6)) :
    (waveMgr.currentConfig.bossDifficulty || 1));
  ```
  This ensures boss HP scales correctly even without zone/node context.

- **`startMultiplayerCombat()`** (`main.js:649-669`): Optionally pass difficulty to wave config builder. At line 656, change:
  ```
  resetWaveManager(waveMgr);
  ```
  to:
  ```
  resetWaveManager(waveMgr, buildWaveConfigs(1));
  ```
  Import `buildWaveConfigs` is not needed since `resetWaveManager` already calls it internally — but making it explicit with a difficulty param requires exporting `buildWaveConfigs` from wave.js. Alternative: add a `difficulty` param to `resetWaveManager` that forwards to `buildWaveConfigs(difficulty)`.

  **Chosen approach**: Modify `resetWaveManager(mgr, externalConfigs, difficulty)` to pass difficulty through:
  ```
  var configs = externalConfigs || buildWaveConfigs(difficulty);
  ```
  Then `startMultiplayerCombat()` calls `resetWaveManager(waveMgr, null, 1)` (or could derive difficulty from game state).

  Similarly update `createWaveManager(externalConfigs, difficulty)` at line 39.

### No changes needed

- **`game/js/boss.js`** — Boss creation, HP scaling, loot, and attacks all work correctly already
- **`game/js/bossHud.js`** — Boss HUD display works correctly, triggered by existing code in main.js
- **`game/js/combatSync.js`** — Multiplayer boss sync works correctly (spawn, state, defeat, attack messages)
- **`game/js/mapData.js`** — `buildZoneWaveConfigs()` already correctly assigns boss on final wave; no mini-boss needed for zone combat (zones have 3-8 waves, boss on final is sufficient)
- **`game/js/main.js` `buildNodeWaveConfigs()`** — Voyage chart boss nodes already work correctly

## Order of Operations

1. **Modify `wave.js`**: Add `MINI_BOSS_WAVE` constant, add `baseDifficulty` param to `buildWaveConfigs()`, set `.boss` and `.bossDifficulty` on waves 5 and 10, halve enemies on boss waves. Update `createWaveManager` and `resetWaveManager` signatures to accept optional difficulty.
2. **Modify `main.js` boss spawn handler**: Add `waveMgr.currentConfig.bossDifficulty` as difficulty fallback at line 1332.
3. **Modify `main.js` `startMultiplayerCombat()`**: Pass difficulty when resetting wave manager (line 656).
4. **Smoke test**: Verify bosses spawn at waves 5 and 10 in browser, check boss HUD appears, loot drops, and wave 10 victory triggers.

## Testing

- **Wave 5 mini-boss**: Start a default/multiplayer game, advance to wave 5. Verify "battleship" boss spawns alongside ~half the normal enemy count. Boss HUD should appear.
- **Wave 10 zone boss**: Advance to wave 10. Verify escalated boss type spawns (carrier at default difficulty). Boss HUD should appear. After defeating boss + enemies, victory should trigger.
- **Boss HP scaling**: Check boss HP at wave 5 (difficulty 1 → hpScale 1.0 → 80hp battleship) vs wave 10 (difficulty 3 → hpScale 1.4 → ~84hp carrier).
- **Loot drops**: Defeat a boss, verify gold/upgrade/repair loot drops and officer recruitment fires.
- **Zone combat unaffected**: Start a zone (e.g. Iron Strait), verify boss still only appears on final wave, no regressions.
- **Voyage chart unaffected**: Start a voyage chart run, verify boss nodes still work correctly.
- **Multiplayer**: Host a multiplayer session, verify boss spawn syncs to all clients via `sendBossSpawn`.
- **Edge cases**:
  - Player dies on wave 5 boss wave → game over should trigger normally
  - Boss defeated but enemies remain → wave should not complete until all enemies dead too
  - Boss defeated but enemies already dead → wave should complete immediately

## Risks

- **Signature change to `createWaveManager`/`resetWaveManager`**: All existing callsites pass either no args or `externalConfigs` — adding optional `difficulty` param won't break them since `undefined` falls through to default.
- **Multiplayer desync**: Boss type is deterministic from config (not random), so host and clients will agree. Boss spawn sync already exists via `combatSync.sendBossSpawn`. Low risk.
- **Two bosses in one run**: Wave 5 spawns a boss, then wave 10 spawns another. The code cleans up `activeBoss` on wave complete (`main.js:1351-1354`), so only one boss is active at a time. Verify the wave 5 boss is fully cleaned up before wave 10 starts.
- **Enemy count on boss waves**: Halving enemies keeps encounters manageable. With wave 5 defaults: `BASE_ENEMIES + ENEMIES_PER_WAVE * 4 = 3 + 8 = 11`, halved to 5. Wave 10: `3 + 18 = 21`, halved to 10. These feel reasonable alongside a boss.
