# Plan: GLB asset loader — GLTFLoader + DRACOLoader replacing FBXLoader

## Issue
#117 — Migrate all 3D model loading from FBX/FBXLoader to Draco-compressed GLB/GLTFLoader for smaller files and faster loading.

## Analysis

### Current state
- **246 FBX files** in `game/assets/models/` used at runtime (ships, islands, terrain, environment props)
- **239 FBX source files** in `game/assets/Palmov Island/` (original asset packs — not loaded at runtime)
- All model loading goes through `fbxVisual.js` (`loadFbxVisual()`) except `testLab.js` which has its own inline `FBXLoader` usage
- `FBXLoader` imported from Three.js CDN at `three/addons/loaders/FBXLoader.js`
- No GLTFLoader or DRACOLoader currently in use

### Model loading pipeline
`fbxVisual.js:loadFbxVisual(path, fitSize, flatShaded)` does:
1. Cache check → load via `FBXLoader` with texture URL remapping
2. Clone cached template
3. `fitToSize()` — normalize scale + center
4. `applyFlat()` — replace all materials with `MeshToonMaterial` (cartoon look)
5. `enforceTriBudget()` — mobile triangle decimation via `getQualityConfig()`

### Texture handling
FBX models reference `Texture Main.png` which gets remapped via `remapTextureUrl()` to either `assets/textures/ships.png` or `assets/textures/locations.png` based on the model path. GLB files embed or reference textures differently — after conversion we need to verify if textures are baked in or still need remapping.

### Step 0: Conversion script — `scripts/convert-fbx-to-glb.sh` (create)
- Bash script that batch converts all 246 FBX files in `game/assets/models/` to Draco-compressed GLB
- Uses `FBX2glTF --binary` for FBX→GLB, then `gltf-transform draco` for compression
- Preserves directory structure, outputs `.glb` alongside (or replacing) `.fbx`
- Handles spaces in filenames (many Palmov assets have spaces)
- Logs conversion results and any failures
- Documents usage in script header comments (satisfies "conversion script documented" AC)

## Risks
- **Texture embedding**: FBX2glTF may or may not embed textures. If textures don't transfer, the `remapTextureUrl` logic needs to be adapted for GLTFLoader's loading manager rather than removed. Test with first model before batch converting.
- **GLB cloning**: `tpl.clone(true)` on GLTF scenes may behave differently than FBX groups — materials/textures might not deep-clone correctly. Need to test clone fidelity.
- **DRACOLoader decoder path**: Requires WASM decoder files from CDN. The Three.js CDN path (`examples/jsm/libs/draco/`) should work but needs verification with the v0.160.0 CDN URL.
- **Spaces in filenames**: Many Palmov assets have spaces. The `encodeURI()` in loadTemplate handles this for FBX — verify GLTFLoader handles encoded URIs similarly.
- **Large commit**: 246 binary files deleted + 246 new binary files added = large git diff. May need `git lfs` or split commits. The Palmov source pack (239 more FBX files) makes this even larger.
- **testLab.js has duplicated loader code**: It has its own `loadTemplate()`, `remapTextureUrl()`, `applyFlat()`, `fitToSize()` — ideally refactor to use `glbVisual.js` shared functions, but that's a nice-to-have beyond issue scope.
- **DRACOLoader singleton**: DRACOLoader should ideally be created once and shared, not per-load-call. Initialize once at module level in `glbVisual.js`.
