# Plan: Remove visible gun/turret models — projectiles spawn directly from ship hull

## Issue
#156 — Remove all visible turret/gun meshes; projectiles spawn from invisible hull fire points for all ship types (player, enemy, boss) with muzzle flash effects.

## Analysis

### Current state
The codebase already underwent a partial migration from the old turret system (`turret.js`) to a unified weapon system (`weapon.js`). However two problems remain:

1. **Dead code**: `game/js/turret.js` (316 lines) still exists on disk. It was the original turret system with visible mesh rotation and aiming. It has been fully superseded by `weapon.js` but was never deleted. No file imports it — it's orphaned dead code.

2. **Missing muzzle flash on enemy/boss fire**: The player weapon system (`weapon.js`) already spawns muzzle flash effects via `spawnFlash()`, but enemies (`enemy.js`) and bosses (`boss.js`) fire projectiles without any visual flash feedback. This makes it hard to tell when/where they fire.

3. **Stale backward-compat alias**: `enemy.js` sets `group.userData.turret = portFP` as a backward-compat alias that is unused and misleading (it was from the old turret system). Same in `applyEnemyOverrideAsync`.

### What's already correct (no changes needed)
- **Player ship fire points** (`ship.js:67-71`): Already invisible `Object3D` markers at port, starboard, bow — no turret meshes.
- **Player ship classes** (`shipModels.js`): All 4 classes (destroyer/sloop, cruiser/brigantine, carrier/galleon, submarine/man-o-war) already use invisible `Object3D` fire points stored in `userData.turrets`.
- **Enemy fire points** (`enemy.js:169-172`): Already invisible `Object3D` at port/starboard, stored in `userData.firePoints`. The `enemyFire` function correctly picks port vs starboard based on player angle.
- **Boss fire points** (`bossModels.js`): Battleship (4 fire points) and carrier (2 fire points) already use invisible `Object3D` in `userData.turrets`. Kraken uses tentacle attacks (no fire points needed).
- **Player weapon system** (`weapon.js`): Already uses `getWorldPosition()` on fire points, has muzzle flash via `spawnFlash()`, no turret rotation code.
- **Boss fire origin** (`boss.js:224-241`): `getBossFireOrigin()` correctly picks the best-aligned fire point using dot product.
- **FBX override flows** (`ship.js:83-107`, `enemy.js:187-203`, `boss.js:85-108`): All correctly re-attach fire points after FBX model loads.

## Changes

### game/js/turret.js (delete)
- This 316-line file is dead code — no module imports it
- It was the original turret system with `createTurretSystem`, `aimTurrets`, `fire`, `updateTurrets`, `screenToWorld`
- All functionality is now in `weapon.js` with a better multi-weapon design
- Delete the entire file

### game/js/enemy.js (modify)
- **Add muzzle flash geometry** (after line 80): Add `flashGeo` and `flashMat` variables, initialize them in `ensureGeo()` — sphere geometry matching player's flash style
- **Add `spawnEnemyFlash` function** (after `ensureGeo`): Creates a flash mesh at the fire position, adds to `manager.effects[]`
- **Add `effects` array to manager** (`createEnemyManager`, ~line 216): Initialize `effects: []` in the returned object
- **Clean up effects on reset** (`resetEnemyManager`, ~line 230): Loop through and remove effect meshes from scene, reset `effects: []`
- **Call flash on fire** (`enemyFire`, ~line 578): After creating the projectile mesh, call `spawnEnemyFlash(manager, scene, barrelTip)`
- **Add `updateEnemyEffects` function**: Fade flash opacity from 1→0 over 0.08s, expand scale, remove when expired — matches player flash behavior
- **Call update in main loop** (`updateEnemies`, ~line 536): Call `updateEnemyEffects(manager, dt, scene)` after `updateParticles`
- **Remove `userData.turret` alias** (line 172 and line 199): Delete the backward-compat alias lines `group.userData.turret = portFP` and `mesh.userData.turret = firePoints[0] || null`

### game/js/boss.js (modify)
- **Add muzzle flash geometry** (after line 60): Add `bossFlashGeo` and `bossFlashMat` variables, initialize in `ensureGeo()`
- **Add `spawnBossFlash` function** (after `ensureGeo`): Creates a flash mesh at fire position, adds to `boss.effects[]`
- **Add `effects` array to boss state** (`createBoss`, ~line 148): Add `effects: []` to the returned boss object
- **Call flash on fire** (`fireBossProjectile`, ~line 247): After creating projectile mesh, call `spawnBossFlash(boss, scene, origin)`
- **Add `updateBossEffects` function**: Identical fade/scale logic as enemy effects — 0.08s lifetime
- **Call update in main loop** (`updateBoss`): Call `updateBossEffects(boss, dt, scene)` at end of both sinking and alive branches
- **Clean up effects on remove** (`removeBoss`, ~line 640): Loop through `boss.effects` and remove meshes from scene

## Risks
- **FBX override timing**: Fire points are re-attached asynchronously — if a ship fires before the FBX loads, the fire points are still in the procedural mesh so this should be fine (already handled)
- **Kraken boss has no fire points**: This is intentional — kraken uses tentacle attacks, not projectile fire. `getBossFireOrigin` falls back to offset calculation if no fire points exist
- **No existing tests**: Manual verification required; no automated test suite exists yet
