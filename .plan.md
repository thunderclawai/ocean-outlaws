# Plan: Remove visible gun/turret models — projectiles spawn directly from ship hull

## Issue
#156 — Remove visible gun/turret meshes from all ships; projectiles spawn from invisible hull fire points with muzzle flash.

## Analysis

The bulk of this work was already completed in commit `1b8896c` (PR #164), which landed on `main`. The current codebase state:

**Already done:**
- All ship types (player, enemy, boss) use invisible `Object3D` fire points — no visible turret/gun meshes exist
- `shipModels.js`: All 4 player classes (destroyer/Sloop, cruiser/Brigantine, carrier/Galleon, submarine/Man-o'-War) define fire points as `Object3D` markers with comment "no turret mesh"
- `enemy.js` (`buildEnemyMesh`): Enemy fire points are invisible `Object3D` markers at port/starboard positions
- `bossModels.js`: Battleship and carrier bosses use invisible `Object3D` fire points
- `ship.js` fallback mesh: Fire points are invisible `Object3D` markers
- Player weapon system (`weapon.js`): Correctly gets fire point world position, spawns muzzle flash
- Enemy fire (`enemyFire` in `enemy.js`): Correctly picks port/starboard fire point, gets world position
- Boss fire (`getBossFireOrigin` in `boss.js`): Correctly selects best-aligned fire point
- Fire points are parented to ship mesh groups (move with ship)
- `placeTurretsFromBounds` does not exist — already removed
- No turret rotation/aiming animation code exists

**Remaining issues to address:**

1. **`turret.js` is dead code** — 317 lines, not imported by any module. It was the original turret system, now fully superseded by `weapon.js`. Should be deleted.

2. **`userData.turret` (singular) backward compat alias in `enemy.js`** — Set at lines 162 and 190 but never read anywhere. Dead code that should be removed.

3. **Enemy projectiles have no muzzle flash** — `enemyFire()` (enemy.js:528) spawns projectiles from fire points correctly but does NOT spawn a muzzle flash effect. Player weapons get a flash via `spawnFlash()` in weapon.js, but enemies have no equivalent. The acceptance criteria requires "Muzzle flash particle effect at fire point on shot" for all ships.

4. **Boss projectiles have no muzzle flash** — `fireBossProjectile()` (boss.js:232) spawns projectiles from fire points but has no muzzle flash effect.

5. **`console.log("[SFX] FIRE turret")` in turret.js** — This is in the dead turret.js file and will be removed with it, but worth noting no similar debug logs remain in weapon.js or enemy.js.

## Changes

### game/js/turret.js (delete)
- Dead code: not imported by any module in the codebase
- Fully superseded by `weapon.js` which handles all player weapon types, projectile physics, hit detection, and effects
- 317 lines of unused code

### game/js/enemy.js (modify)
- **Remove `userData.turret` alias** (lines 162, 190): Delete `group.userData.turret = portFP;` and `mesh.userData.turret = firePoints[0] || null;` — set but never read
- **Add muzzle flash to `enemyFire()`** (after line 563): After spawning the projectile mesh and adding it to the scene, create a muzzle flash effect at `barrelTip` position. Use same pattern as weapon.js `spawnFlash()`:
  - Create shared `flashGeo` (SphereGeometry 0.3) and `flashMat` (MeshBasicMaterial yellow, transparent) in `ensureGeo()`
  - Add a `spawnEnemyFlash()` helper that creates a flash mesh at the fire point, adds to scene, and pushes to a new `manager.effects` array
  - Update `updateEnemyProjectiles` or add a new `updateEnemyEffects()` function to fade and remove flash effects (0.08s lifetime, scale up, fade out)
  - Call the new effect update from `updateEnemies()`

### game/js/boss.js (modify)
- **Add muzzle flash to `fireBossProjectile()`** (after line 237): After spawning the projectile, create a muzzle flash at the origin position. Pattern:
  - Create shared flash geometry/material in `ensureGeo()`
  - Add a `spawnBossFlash()` helper
  - Store flash effects in `boss.effects` array (new field, initialized in `createBoss`)
  - Add `updateBossEffects()` to fade/remove flashes
  - Call from `updateBoss()` alongside other update functions
  - Clean up effects in `removeBoss()`

## Risks
- **FBX model override timing**: Fire points are re-attached after async FBX load. If a shot fires during the brief window while the FBX is loading and children are being swapped, the fire point could momentarily be detached. This is pre-existing and low-risk (sub-second window).
- **Boss effects array**: Adding a new `effects` array to boss state. Must ensure `createBoss` initializes it and `removeBoss` cleans it up, or stale meshes will leak in the scene.
- **Enemy effects management**: The enemy manager doesn't currently have an `effects` array. Need to add it to `createEnemyManager` and `resetEnemyManager` to properly clean up.
