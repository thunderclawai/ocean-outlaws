# Plan: Remove visible gun/turret models — projectiles spawn directly from ship hull

## Issue
#156 — Remove visible turret/gun meshes from all ship types (player, enemy, boss). Projectiles spawn from invisible hull fire points. Fixes enemy projectile origin bug and visual mismatch.

## Analysis

### Current turret system
The game has **three independent turret/fire systems** that all create visible turret meshes:

1. **Player ships** (`shipModels.js` + `weapon.js`): Each ship class (destroyer, cruiser, carrier, submarine) builds `THREE.Group` turret objects with cylinder+barrel geometry, stored in `mesh.userData.turrets[]`. `weapon.js:createWeaponState()` reads these turret groups. `weapon.js:aimWeapons()` rotates them toward targets. `weapon.js:fireWeapon()` alternates between turrets and spawns projectiles from `barrelTip` at local offset `(0, 0.1, 0.7)` via `turret.localToWorld()`.

2. **Enemy ships** (`enemy.js`): `buildEnemyMesh()` creates a single turret group with cylinder+barrel, stored in `mesh.userData.turret` (singular). `enemyFire()` uses `turret.localToWorld(barrelTip)` at offset `(0, 0.08, 0.5)` for projectile origin. The turret is aimed at the player via `turret.rotation.y`. When FBX override loads, `placeEnemyTurretFromBounds()` repositions and hides the turret (`turret.visible = false`), but the turret group is still used for fire position.

3. **Boss ships** (`bossModels.js` + `boss.js`): Battleship and carrier boss meshes build multiple turret groups in `mesh.userData.turrets[]`. Boss firing (`fireBossProjectile()`) does NOT use turrets at all — it calculates `startX/startZ` directly from `boss.posX/posZ + offset`. The turrets are purely decorative but get repositioned via `placeTurretsFromBounds()` on FBX override.

4. **Fallback ship** (`ship.js:buildShipMesh()`): The original procedural ship also builds two turret groups. This is only used when no `classConfig` is provided.

### The bugs
- **Enemy projectile origin**: When FBX overrides load, `placeEnemyTurretFromBounds()` repositions the turret but sets `turret.visible = false`. The turret's world position may be wrong if the FBX model's bounds differ significantly from expected. More critically, if no FBX override loads, the procedural turret position may not match the visual hull.
- **Visual mismatch**: Modern gun turrets (cylinders + barrels) look wrong on pirate sailboats.

### Key dependencies
- `weapon.js:createWeaponState()` (line 58-67): Reads `ship.mesh.userData.turrets` to populate `turretGroups[]`
- `weapon.js:aimWeapons()` (line 91-103): Iterates `turretGroups`, calls `getWorldPosition()` and sets `rotation.y`
- `weapon.js:fireWeapon()` (line 105-163): Uses `turretGroups[idx].localToWorld(barrelTip)` for spawn position
- `turret.js:createTurretSystem()` (line 45-58): Also reads `userData.turrets` (legacy, possibly unused in main flow)
- `turret.js:aimTurrets()` / `turret.js:fire()`: Legacy turret system, same pattern
- `enemy.js:enemyFire()` (line 555-592): Uses `userData.turret.localToWorld()` for spawn position
- `boss.js:fireBossProjectile()` (line 216-231): Uses position math directly, no turret dependency

### Fire point design
Replace visible turret groups with invisible `THREE.Object3D` markers ("fire points") at hull-relative positions:
- **Player ships**: Port broadside, starboard broadside, bow (3 fire points minimum, more for larger ships)
- **Enemy ships**: Port broadside, starboard broadside (2 fire points)
- **Boss battleship**: 4 fire points matching current turret positions
- **Boss carrier**: 2 fire points matching current turret positions
- **Boss kraken**: No turrets currently, no changes needed

## Risks
- **weapon.js barrel offset removal**: The current code offsets `(0, 0.1, 0.7)` from turret local space. With fire points at the exact position, projectiles spawn from those coordinates. If fire point Y is too low, projectiles may immediately hit water. Fire point Y values must be above water level (~0.3+).
- **turretGroups array length**: weapon.js alternates turrets via `shotCount % turretGroups.length`. Changing from 2 turrets to 3 fire points changes the alternation pattern — this is fine but means projectile fire rate per-side changes.
- **FBX override timing**: Fire points are Object3D children of the mesh group. When `applyShipOverrideAsync` clears children and re-adds the FBX visual, fire points will be removed if not explicitly preserved. Must snapshot and re-add fire points just like turrets were re-added before.
- **boss.js firing**: `fireBossProjectile()` doesn't use turret groups — it uses raw position math. This means boss projectile origin won't change unless we also update that function to use fire points. The issue specifically mentions boss projectiles should spawn from hull fire points, so this needs to be addressed.
- **turret.js may be dead code**: main.js only imports from weapon.js, never turret.js. If turret.js is fully unused, changes there are safety-only. Verify no other file imports from turret.js.
