# Plan: Bug: legacy terrain/land objects still spawning alongside Palmov compositions

## Issue
#147 — Old heightmap-based procedural terrain mesh renders alongside Palmov FBX composition islands, causing visual clutter. Heightmap collision also leaks through as a secondary layer even after compositions load.

## Analysis

### Current architecture

**`terrain.js`** owns two systems in one file:
1. **Legacy heightmap system** (lines 7–471): generates a 128×128 noise heightmap, then builds a marching-squares 3D mesh (`buildTerrainMesh`) with vertex-colored green/brown terrain. This mesh is the `baseMesh`.
2. **Palmov composition bridge** (lines 474–516): `createTerrain()` calls `addCompositeFieldVisual()` (async) which loads FBX island compositions from `data/compositePresetsPalmov30.json`. On success it hides `baseMesh` and sets `useVisualCollision = true`. On failure it falls back to `addTieredIslandFieldVisual()`.

**Bug 1 — visual**: `baseMesh` is always built and starts **visible**. It's only hidden asynchronously after compositions finish loading. During the loading window, both the green heightmap mesh and the FBX composition islands are visible simultaneously.

**Bug 2 — collision leakthrough**: `isLand()` (line 208–212) and `getTerrainHeight()` (line 215–219) have a logic error. When `useVisualCollision` is true and a point is NOT inside a visual collider, they fall through to the heightmap check (`sampleHeight`), creating invisible collision walls where no terrain is visible:
```js
// Current — heightmap always provides secondary collision:
if (terrain.useVisualCollision && pointInVisualLand(...)) return true;
return sampleHeight(terrain, worldX, worldZ) > SEA_LEVEL; // ← always runs if not in visual land
```

**`terrainComposite.js`** — the Palmov system. Works correctly. No changes needed.

**`ocean.js`** — `setTerrainMap()` sets a `uHasTerrain` flag based on `terrain.heightmap` existing, but the flag is never read by `updateOcean()`. Effectively dead, no change needed.

**`port.js`** — `initPorts()` is called synchronously after `createTerrain()`. It uses `getTerrainHeight()` and `isLand()` to find coastline positions. These must work synchronously during the loading window (before composites are ready), which means the heightmap must still be generated and queryable during loading.

**Consumers of terrain collision** (all via `terrain.js` exports): `ship.js`, `enemy.js`, `boss.js`, `weapon.js`, `collision.js`, `nav.js`, `port.js`, `crate.js`, `merchant.js`, `main.js`. None reference `baseMesh` or heightmap internals directly — they all go through the public API (`isLand`, `collideWithTerrain`, `terrainBlocksLine`, etc.).

### Key files
- `game/js/terrain.js` — primary target, owns legacy mesh + collision routing
- `game/js/terrainComposite.js` — Palmov system, no changes
- `game/js/main.js` — calls `createTerrain`, no changes needed (terrain object shape stays compatible)
- `game/js/port.js` — depends on synchronous terrain queries during loading

## Changes

### game/js/terrain.js (modify)

#### 1. Remove `buildTerrainMesh()` and all its helpers
Remove the following functions and data structures (lines ~299–471):
- `edgeLerp()` (line 301)
- `heightToY()` (line 308)
- `EDGE_FROM`, `EDGE_TO` arrays (lines 317–318)
- `buildTerrainMesh()` (line 323)
- `pushTri()` (line 419)
- `MARCH_TABLE` array (lines 426–440)
- `marchTris()` (line 442)
- `colorTriangle()` (line 454)

#### 2. Remove dead constants
- `TERRAIN_HEIGHT` (line 12) — only used by removed `heightToY()` and `colorTriangle()`
- `BEACH_HEIGHT` (line 13) — only used by removed `heightToY()` and `colorTriangle()`
- `BOUNCE_STRENGTH` (line 19) — defined but never referenced anywhere
- `TERRAIN_VISUAL_Y_OFFSET` (line 20) — defined in terrain.js but never used here (terrainComposite.js has its own copy)

#### 3. Fix `isLand()` collision leakthrough (line 208–212)
When `useVisualCollision` is true, return visual-only result without falling through to heightmap:
```js
export function isLand(terrain, worldX, worldZ) {
  if (!terrain) return false;
  if (terrain.useVisualCollision) return pointInVisualLand(terrain, worldX, worldZ, COLLISION_RADIUS);
  return sampleHeight(terrain, worldX, worldZ) > SEA_LEVEL;
}
```

#### 4. Fix `getTerrainHeight()` collision leakthrough (line 215–219)
Same pattern — exclusive branch, no fallthrough:
```js
export function getTerrainHeight(terrain, worldX, worldZ) {
  if (!terrain) return -1;
  if (terrain.useVisualCollision) return pointInVisualLand(terrain, worldX, worldZ, COLLISION_RADIUS) ? 1 : -1;
  return sampleHeight(terrain, worldX, worldZ);
}
```

#### 5. Simplify `createTerrain()` (line 474–516)
- Keep `generateHeightmap()` + `ensureNavigable()` (needed for port placement during sync loading window, and for tiered fallback's `collectLandPoints`)
- **Remove** `buildTerrainMesh(heightmap)` call
- **Remove** `baseMesh` creation and `mesh.add(baseMesh)`
- **Remove** `baseMesh` from terrain object
- Create mesh group as empty `new THREE.Group()` (compositions add children to it)
- In the async `.then()` callback: remove all `baseMesh.visible` toggling
- Keep `useVisualCollision` starting as `false` (heightmap collision used during async loading window for ports etc.), switching to `true` after composites load

#### 6. Keep (do not remove)
- `sampleHeight()` — still needed by `isLand`/`getTerrainHeight` during the loading window before composites are ready
- `generateHeightmap()`, `ensureNavigable()`, noise functions (`hashCoord`, `smoothstep`, `noise2D`, `fbm`, `gaussianBlur`) — needed for tiered fallback placement via `collectLandPoints`
- `CELL_SIZE` — used by legacy `collideWithTerrain`/`terrainBlocksLine` heightmap paths during loading window
- `MAP_SIZE`, `GRID_RES`, `SEA_LEVEL`, `NOISE_SCALE`, `OCTAVES`, `PERSISTENCE`, `LACUNARITY`, `SPAWN_CLEAR_RADIUS` — used by heightmap generation
- `COLLISION_RADIUS`, `VISUAL_COLLIDER_PAD` — used by visual collision paths
- Edge boundary constants and functions — unrelated to terrain visuals
- All other public exports unchanged

### No changes needed

- **`game/js/terrainComposite.js`** — this IS the Palmov system we're keeping
- **`game/js/main.js`** — `createTerrain` return shape is compatible (mesh group still works, no `baseMesh` was referenced externally). `setTerrainMap` in ocean.js still works since `terrain.heightmap` is still set
- **`game/js/ocean.js`** — `setTerrainMap` checks `terrain.heightmap` which still exists; `uHasTerrain` flag is unused by rendering anyway
- **`game/js/port.js`** — `findCoastlinePositions` calls `getTerrainHeight`/`isLand` synchronously. During loading window `useVisualCollision` is false, so heightmap is used. After composites load, ports are already placed. No change needed.
- **`game/js/ship.js`, `enemy.js`, `boss.js`, `weapon.js`, `collision.js`, `nav.js`, `crate.js`, `merchant.js`** — all use public terrain API which remains unchanged

## Order of Operations
1. Remove dead constants (`TERRAIN_HEIGHT`, `BEACH_HEIGHT`, `BOUNCE_STRENGTH`, `TERRAIN_VISUAL_Y_OFFSET`) from terrain.js
2. Remove `buildTerrainMesh()` and all helper functions/data it depends on (~170 lines)
3. Fix `isLand()` — add exclusive `useVisualCollision` branch (prevent heightmap leakthrough)
4. Fix `getTerrainHeight()` — same exclusive branch fix
5. Simplify `createTerrain()` — remove baseMesh creation, remove baseMesh visibility toggling in async callback
6. Verify: load game, confirm no green heightmap mesh appears, confirm FBX compositions still spawn, confirm ship collisions work, confirm ports spawn at coastlines

## Testing
- **Visual**: Load any zone — only FBX composition islands should be visible, no green/brown procedural terrain mesh
- **Collision**: Sail near an FBX island — ship should collide with visual collider boxes, not invisible heightmap walls
- **Ports**: Ports should still appear at coastline positions near islands
- **Fallback**: If `compositePresetsPalmov30.json` fails to load, tiered island fallback should still place FBX islands using heightmap seed points
- **Edge cases**:
  - Fast zone transitions: terrain removed/recreated rapidly
  - Mobile quality settings: reduced composite instances should still work
  - Multiplayer: terrain seed sharing unchanged

## Risks
- **Port placement timing**: Ports are placed synchronously during the loading window using heightmap. After composites load, collision switches to visual-only. If a port ended up on heightmap land that has no corresponding composition island, the port would float in open water. This is a pre-existing issue (the heightmap and compositions don't perfectly overlap) and is not made worse by this change.
- **Brief collision gap**: Between `createTerrain()` returning and composites finishing async load, heightmap collision is active but invisible. Ships could briefly collide with invisible terrain. This window is typically <1 second and no worse than current behavior (where the visible legacy mesh is the indicator).
- **Tiered fallback dependency**: If someone removes `generateHeightmap` in a future cleanup, the tiered island fallback (`addTieredIslandFieldVisual`) would break since it uses `collectLandPoints(heightmap, ...)`. The heightmap is kept for this reason.
